# Project 11 - Infrastructure Changes with Branching Policy

## Objective
Practice a controlled infrastructure change using Git branching and Pull Request review.

## Workflow
1. Create a feature branch.
2. Make an infrastructure change.
3. Commit the change.
4. Push the feature branch to GitHub.
5. Create a Pull Request.
6. Review the change.
7. Merge into main.

## Branching Policy
- main: stable branch
- feature/*: infrastructure changes and development work

## Goal
Avoid direct changes to the main branch and ensure infrastructure changes
are reviewed before merging.
